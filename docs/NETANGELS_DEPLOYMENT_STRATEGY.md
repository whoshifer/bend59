# BEND Next.js — стратегия развёртывания на NetAngels

## Назначение

Новая версия BEND — это **самостоятельное Next.js-приложение** с PostgreSQL и закрытой административной панелью. Она не зависит от WordPress, PHP-плагинов или внешней CMS. Контент, товары, серии, документы, изображения, кнопки, SEO-настройки и заявки хранятся в базе данных и меняются через `/admin`.

## Рабочая схема

| Сервис | Ответственность | Постоянные данные |
|---|---|---|
| `app` | Next.js: публичный сайт, API, админка, авторизация и приём заявок | Нет; приложение собирается из исходного кода |
| `db` | PostgreSQL: все записи сайта, учётные данные администратора и заявки | Docker volume `postgres_data` |
| `caddy` | HTTPS, домен и обратный прокси к приложению | Конфигурация и сертификаты в Docker volumes |
| `uploads` | Реальные фото и загружаемые PDF | Docker volume `uploads_data`, доступный только приложению |

> Схема намеренно разделяет код, базу и медиа. Поэтому обновление приложения не удаляет каталог, изображения, документы и заявки.

## Почему Docker Compose

NetAngels указывает Docker как доступный образ для облачного VDS и допускает запуск нескольких сервисов на одном сервере.[1] В их материалах также показана работа с Docker Compose для многоконтейнерных решений; отдельно отмечено, что PostgreSQL требует больше 1 ГБ оперативной памяти.[2]

Для BEND это означает, что целевая площадка должна быть **облачным VDS с Docker**, а не обычным PHP-хостингом. На сервер переносится один проект с `docker-compose.yml`, переменными окружения и резервной копией базы. Панель, исходники и база остаются под контролем владельца.

## Переменные окружения

| Переменная | Назначение | Где хранить |
|---|---|---|
| `POSTGRES_DB` | Имя базы данных | `.env` только на сервере |
| `POSTGRES_USER` | Пользователь PostgreSQL | `.env` только на сервере |
| `POSTGRES_PASSWORD` | Пароль базы | `.env` только на сервере |
| `DATABASE_URL` | Строка подключения приложения | `.env` только на сервере |
| `AUTH_SECRET` | Подпись сессионного cookie | `.env` только на сервере |
| `ADMIN_EMAIL` | Первый администратор при инициализации | `.env` только на сервере |
| `ADMIN_PASSWORD` | Первый пароль администратора | `.env` только на сервере, затем удалить/сменить |
| `SITE_URL` | Канонический HTTPS-адрес сайта | `.env` только на сервере |

Ни один из этих параметров не попадает в Git, клиентский JavaScript или публичный HTML.

## Резервное копирование

1. Ежедневно выгружать PostgreSQL через `pg_dump` в закрытую папку на сервере или во внешнее защищённое хранилище.
2. Отдельно архивировать Docker volume с медиафайлами.
3. Перед обновлением приложения выполнять резервную копию базы и медиа.
4. Проверять восстановление на отдельной локальной копии перед критичными изменениями.

## Проверка перед публикацией

| Проверка | Ожидаемый результат |
|---|---|
| `docker compose up -d --build` | Все три сервиса запускаются без ошибок |
| Публичная главная | Открывается по HTTPS и корректно выглядит на mobile/desktop |
| `/admin` | Требует авторизацию и позволяет менять контент |
| Медиа | Новое фото и PDF видны после загрузки и переживают перезапуск контейнера |
| Заявка | Сохраняется в базе; SMTP настраивается отдельно перед запуском |
| Бэкап | Дамп PostgreSQL и архив медиа успешно создаются |
