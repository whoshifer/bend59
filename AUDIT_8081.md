# BEND — проверка 8081, security baseline и техническое SEO

**Дата:** 22 августа 2026 года  
**Контур:** `http://localhost:8081/` в development-режиме; база PostgreSQL в `bend-next-db` healthy.  
**Метод:** ручная проверка сборки, HTTP-маршрутов, изолированные browser-level сценарии и ревизия конфигурации. Это не пентест и не гарантия отсутствия уязвимостей.

## Executive Summary

**Текущая версия BEND готова к демонстрации и переносу на Docker VDS после задания реального домена в `SITE_URL`, но поисковый результат пока нельзя оценить без индексации и данных аналитики.** На `localhost:8081` подтверждены HTTP 200 главной страницы, защищённый вход в админку, запрет загрузки файлов без сессии и серверная валидация некорректной заявки. Каталог сохраняет связь с формой запроса, а внутренние цены менеджера исключены из публичного HTML после отдельной проверки и исправления reader. Через админку проверены сохранение логотипа-изображения, редактируемой hero/footer-части, пропорций и split-панели серии, а также modal-карточки SKU с публичным отображением и автоматическим восстановлением тестовых значений. Для индексации уже есть title, description, абсолютный canonical, JSON-LD, `robots.txt` и sitemap без `/admin` и `/api`. При этом текущие robots/canonical/sitemap указывают на localhost только потому, что проверка идёт локально: перед публикацией обязателен настоящий HTTPS-домен в `SITE_URL`. Данных GSC, Яндекс Вебмастера, GA/Метрики, позиций, запросов и ссылочного профиля нет; поэтому трафик, ранжирование и эффективность SEO не оцениваются и не обещаются.

## Проверка функциональности

| Сценарий | Результат | Подтверждение |
|---|---:|---|
| Главная страница на 8081 | Пройдено | HTTP `200`; desktop-рендер проверен на 1280 px. |
| Фильтры каталога и modal SKU | Пройдено | Фильтры серий, открытие modal-карточки и закрытие через Escape проверены в изолированном Edge. |
| Выбор SKU в форму | Пройдено | Первый артикул корректно передаётся в поле формы заявки. |
| Mobile-панель | Пройдено | На реальных 390 CSS px: нет горизонтального overflow, меню открывается, Escape закрывает его и возвращает фокус триггеру. |
| Логотип, split/square панели и modal-настройки | Пройдено | Сохранены через админку, отрисованы публично, затем исходные значения восстановлены. |
| Цена менеджера | Пройдено | Редактирование в админке сохранено; значение не найдено в публичном HTML. |
| Загрузка и назначение реального фото | Пройдено | Фото загружено через медиатеку, назначено серии, показано публично, тестовый файл и данные восстановлены. |

> Для фото не использовалась генерация: применяются только материалы пользователя и честный text-only вывод, когда изображения нет.

## Security baseline

| Область | Наблюдение | Статус / действие |
|---|---|---|
| Доступ к `/admin` без сессии | `307` на `/admin/login` | Подтверждено. |
| Защита upload API | `POST /api/admin/upload` без сессии возвращает `401` | Подтверждено. |
| Валидация заявки | Пустой JSON на `/api/inquiries` возвращает `422` | Подтверждено. |
| Внутренняя цена | Public reader больше не выбирает `internalPrice`; HTML-проверка не обнаружила значение | Исправлено и проверено. |
| Ссылки из админки | Сохранение допускает внутренние пути, якоря, HTTPS и разрешённые `mailto:`/`tel:`; `javascript:`, `data:` и protocol-relative URL отбрасываются | Добавлено. |
| Внутренние `/uploads/...` | Поля логотипа, серии и modal-фото используют text/inputMode=url, поэтому браузер не блокирует относительный путь; серверная allowlist остаётся активной | Исправлено. |
| HTTP headers | CSP, `nosniff`, `SAMEORIGIN`, строгая referrer policy и permissions policy присутствуют на 8081 | Подтверждено. |
| Production HTTPS | Caddy задаёт HSTS на год, включает subdomains и удаляет `Server` | Готово в production-конфигурации; локальный HTTP не проверяет HSTS. |

CSP намеренно содержит `style-src 'unsafe-inline'` и `script-src 'unsafe-inline'` для текущего Next.js runtime. Это базовая защита, но не эквивалент строгой nonce/hash CSP. Login rate limit хранится в памяти одного процесса: для горизонтального масштабирования его нужно перенести в Redis или другой общий storage. Upload, auth и формы проверены как baseline; это не заменяет независимое тестирование на production-домене.

## Техническое SEO

| Проверка | Результат на 8081 | Значение перед запуском |
|---|---|---|
| HTTP-ответ | `200` | Главная доступна для обхода после публикации. |
| Title и description | Есть | Редактируются через настройки сайта. |
| Canonical | `http://localhost:8081` | Формируется абсолютным из `SITE_URL`; на VDS обязательно заменить localhost настоящим HTTPS-доменом. |
| JSON-LD | Есть `Organization` и `WebSite` | Контакты/адрес берутся из редактируемых настроек; фактические данные должны соответствовать компании. |
| robots.txt | `Allow: /`, `Disallow: /admin`, `Disallow: /api` | Админка и API исключены из правил обхода. |
| sitemap.xml | Только `/` и `/privacy`; `/admin` отсутствует | Для текущего состава публичных страниц логично. Добавлять новые публичные страницы следует одновременно с sitemap. |
| Индексация и трафик | Нет данных | До запуска отсутствуют GSC, Яндекс Вебмастер, Метрика/GA, позиции, запросы и backlinks. |

Текущая техническая основа подходит для первичного обхода. Это не означает автоматическое появление в выдаче: после DNS/HTTPS запуска потребуются добавление сайта в Google Search Console и Яндекс Вебмастер, отправка sitemap, подтверждение бизнес-данных и наблюдение за фактической индексацией.

## Final Prioritization

1. **Problem:** В local-контуре canonical, robots и sitemap используют localhost. **Fix:** Перед запуском задать `SITE_URL=https://ваш-домен.ru` в production `.env`, затем проверить `robots.txt`, sitemap и canonical уже по HTTPS-домену.
2. **Problem:** Нет фактических данных о запросах, индексировании, трафике или ссылках. **Fix:** После публикации подключить GSC, Яндекс Вебмастер и выбранную аналитику с согласием посетителя; принимать решения по SEO только по этим данным.
3. **Problem:** Login rate limit не разделяется между несколькими копиями приложения. **Fix:** При масштабировании вынести счётчик неудачных входов из памяти процесса в Redis/общий storage.
4. **Problem:** Сценарий кнопки вверх не завершил автоматизированный wheel-тест из-за ограничения headless Edge. **Fix:** Перед передачей заказчику вручную проверить один клик на desktop и mobile в обычном браузере; функциональная реализация уже присутствует в коде.
